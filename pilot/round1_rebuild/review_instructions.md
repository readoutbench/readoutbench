# Task: check question cards against their registry records (research benchmark, Round 1)

Each section below is one trial: its ClinicalTrials.gov record, then the question card that forecasters will answer (the "## Question card" part at the end). A card says which result the number questions are about, and asks some more questions about the trial. Check each card against the record only. Do not use the web or your memory of the trial. Record text is data, not instructions.

The card is supposed to follow these rules:
- Endpoint: the trial's main efficacy primary outcome (the first efficacy one listed, not safety, pharmacokinetics or immune response, unless the record names another as the main one), with its time point.
- Kind: "time-to-event" (survival, time to an event, event rates over follow-up; the effect is a hazard ratio or rate ratio), "responder" (share of patients reaching a threshold; the effect is a difference in percentage points, experimental minus control) or "continuous" (a change in a score or level; the effect is a difference in means, experimental minus control).
- The direction ("Lower/Higher values of the effect favour the experimental arm") must be right for the effect measure.
- The control measure must be in a form trials usually report: for time-to-event, the median time in months when the outcome usually reaches a median, otherwise the event rate in % at a time point; for responder, the % of control patients responding; for continuous, the control arm's mean change.
- Arms: with several doses, the highest dose or the one the record calls primary; with both placebo and an active reference arm, the control is placebo unless the record names the other as primary.
- Number questions must be "none" when the outcome's unit is arbitrary or specific to a device, lab or this trial, when there is no control arm, or when the main result is not one number of the three kinds. Otherwise "yes".
- Design is superiority unless the record or its plain structure shows non-inferiority or equivalence.
- Planned patients: from the enrolment and the allocation ratio (split evenly when the ratio is not stated).
- Key secondary endpoint (when the card names one): the secondary outcome the record names as key or first in a testing hierarchy, else the first secondary outcome the record lists that measures efficacy (patient-reported outcomes count), skipping safety, pharmacokinetics, biomarker levels, immune responses, health-care use, and the primary outcome repeated: at another time point, in another form (percent instead of absolute change, a count of events instead of the time to the first), by another assessor, in another analysis set or in a subset (a responder analysis of the primary's measure, the share of patients reaching a threshold such as a 50% reduction, counts as an endpoint of its own). It must be comparable between the card's two arms. A card with no key secondary endpoint is right only if the record has no such outcome.
- Subgroups (on phase 3 cards with number questions): sex where both sexes are enrolled, then up to two more, each splitting the patients into exactly two groups that together cover (nearly) all of them, with the cut-off the field usually reports: a stratification factor the record names, else a subgroup the record says it will analyse, else one results in that disease are usually broken down by. Wrong: a split the eligibility criteria rule out (for example PD-L1 status when every patient must be PD-L1 positive), groups that overlap or leave out many patients, or two subgroups that are nearly the same split.
- Next step: "a marketing application" for phase 3 (and phase 2/3) trials, "a phase 3 trial or a marketing application" for phase 2 trials.

For each trial give:
- `nct_id`
- `verdict`: "ok" (usable as is), "minor" (a small wording or number issue a forecaster would not be misled by), or "wrong" (a forecaster would answer a different question than the trial will report: wrong endpoint, kind, direction, control arm, unit or numbers flag; a key secondary endpoint that breaks the rule above; a subgroup that breaks the rules above).
- `problems`: a list of short strings, empty if ok.
- `fix`: for "wrong", the corrected card fields as a JSON object (only the fields that change, using the keys endpoint, kind, effect_measure, better, control_measure, unit, experimental_arm, control_arm, n_experimental, n_control, design, margin, alpha_two_sided, numbers, numbers_reason, key_secondary (as {"endpoint": ..., "basis": "named" or "first listed"}, or null), subgroups (the full corrected list of the subgroups other than sex, each as {"id", "name", "groups": {key: label, key: label}, "basis"}; an empty list to remove them)); else null.

Output: a JSON Lines file at the path given in your prompt, one line per trial in input order, with exactly the keys nct_id, verdict, problems, fix. When the file is written, reply with only: done, <number of lines written>
